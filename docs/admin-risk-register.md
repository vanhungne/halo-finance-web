# Admin risk register

| Risk | Surface | Failure | Control |
|---|---|---|---|
| R3 | system config / maintenance | broad platform impact or secret exposure | keep legacy, require backend typed contract and durable audit before V2 |
| R3 | financial correction | ledger corruption or unauthorized money change | no UI command until backend contract and concurrency evidence exists |
| R3 | subscription catalog / availability | rewriting entitlements, deleting a plan referenced by checkout, or retrying an uncertain write as a new command | inactive create, immutable price/duration/grants, protected soft-delete with committed create/activation provenance and zero membership history, current verified actor/version, durable operation/audit and same-key/body retry; billing overlap, client navigation recovery, full-host/restore gates remain |
| R2 | report reply / content state | irreversible or misleading operator action | explicit desired-state labels, server result and conflict handling |
| R1 | support dossier/content | unnecessary personal data exposure or stale private content pages | current persisted Admin per page, version-bound Unicode chunks, no attachment/provider URL, text-only rendering, private/no-store and protected cursor |
| R2 | report type catalog | deletion could race a new report reference, rename could overwrite another edit, uncertain retry could create duplicate types | type row locks plus fresh READ COMMITTED reference query and DB isolation/reference guards; exact version, canonical fingerprint, atomic receipt/audit, same-key frozen retry; used history protected and full-host/recovery/global snapshot gates remain |
| R2 | user lifecycle | account lockout or privacy harm | backend command, reason, expected version and audit required |
| R3 | account role assignment | accidental privilege escalation or loss of the last administrator | allow-listed roles, verified Admin handler, expected version, self-demotion/last-admin guards, token invalidation and durable audit; UI remains closed pending qualification |
| R2 | receipt policy clone | an operator could fork a stale or incomplete classification policy | exact `VersionToken`, serializable transaction, unique policy version, copied rules, idempotent operation/audit receipt and bounded conflict; edit/publication/rule commands remain gated |
| R2 | receipt policy draft update | an operator could weaken classification confidence or overwrite another edit | bounded 0–10000 scoring values, draft-only guard, exact `VersionToken`, serializable transaction, idempotent operation/audit receipt; capability remains closed pending PostgreSQL qualification |
| R2 | receipt policy rules | an operator could create ambiguous, foreign-category or stale classification rules | normalized patterns, active expense-category check, duplicate guard, draft-only guard, shared policy `VersionToken`, serializable idempotent operation/audit receipt; capability remains closed pending PostgreSQL qualification |
| R2 | receipt policy publication | concurrent operators could expose two policies or publish stale rules | PostgreSQL publication lock, retire-first transaction ordering, filtered unique published index, exact `VersionToken`, idempotent operation/audit receipt and bounded race conflict; capability remains closed pending PostgreSQL qualification |
| R3 | business metadata commands | rename or project code/name edits could race, bypass domain invariants or create duplicate identity | verified Admin handler, domain methods, numeric If-Match/body version agreement, serializable transaction, idempotency/audit receipt; capability stays closed pending PostgreSQL evidence |
| R3 | system configuration CRUD | an operator could change runtime behavior, leak credentials or overwrite a newer setting | typed bounded values, secret/credential key deny-list, matching timestamp precondition, serializable operation/audit transaction, post-commit cache invalidation; capability stays closed pending PostgreSQL evidence |
| R1 | account directory | an operator projection could expose unnecessary personal/financial data or produce unstable pages during lifecycle changes | dedicated redacted DTO, verified Admin subject, protected filter cursor, deterministic created/id keyset order and separate lifecycle version command |
| R0 | list/detail reads | 403/500 displayed as empty data | dedicated forbidden/error/empty states |
| R0 | cross-scope data | operator acts on wrong company/project | visible scope indicator and server-filtered query |
